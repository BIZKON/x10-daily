## 1. Что сделано

### Партнёрские версии КП — из одного шаблона

Три партнёра рассылают своё коммерческое предложение, тело документа одно.

| Файл | Роль |
|---|---|
| `landing/kp/template.html` | 🔴 ЕДИНЫЙ источник текста. Правится здесь |
| `landing/kp/main.json` | основное КП (в гите: контакты и так напечатаны в документе) |
| `landing/kp/partners.json` | партнёры — **вне гита**: личные телефоны, репозиторий публичный |
| `scripts/build-kp.mjs` | сборка: `node scripts/build-kp.mjs` |

На выходе четыре самодостаточные страницы: `/kp` (Татьяна Столбова),
`/kp/ivanov/`, `/kp/nemchenko/`, `/kp/kustrya/`. Фото вшивается в HTML как
data-URI — удалили файл на сервере, документ у клиента цел.

🔴 **Собранные страницы несут в шапке «руками не править»:** `landing/index.html`
теперь генерируемый, и правка в нём пропадёт при следующей сборке. То же
записано в CLAUDE.md §9.

⚠️ **Партнёрские страницы едут на прод ОТДЕЛЬНОЙ копией** (`scp` каталогов), а не
через `git pull`: в них личные телефоны, а репозиторий публичный. Основное КП
приезжает из репозитория как обычно.

### Партнёрская программа — построена, выкачена, проверена живым прогоном

Экономика владельца 14.08: **20% продавцу с каждой ПОСТУПИВШЕЙ оплаты**,
наставнику **+5% сверх** 12 месяцев, глубина один уровень, рассрочка максимум
2 месяца. Спека — `docs/superpowers/specs/2026-08-14-partner-cabinet-design.md`.

| Слой | Что |
|---|---|
| Миграция `0034` | `partners` (с `parent_id`), `partner_deals`, `deal_payments`, `partner_accruals`, `partner_payouts` |
| Расчёты | `apps/api/src/lib/partner-money.ts` — чистые функции, 17 тестов |
| Привязка страниц | `apps/api/src/lib/partner-slug.ts` — бронь `username:slug` |
| Маршруты | `routes/partner.ts` (мини-апп), `routes/admin-partners.ts` (владелец) |
| Кабинет партнёра | `apps/miniapp/src/app/(shell)/partner/` |
| Админский раздел | `apps/admin/src/app/partners/` |
| Точки входа | баннер в ленте после третьей карточки + карточка в профиле |

**Решения владельца, которые надо беречь:**

- Партнёрский кабинет — **в мини-аппе**, а не в админке: читатель канала и есть
  вероятный партнёр, вход по Telegram у него уже есть.
- Регистрация **в один тап**, реквизиты спрашиваем при первом начислении:
  анкета отсеяла бы людей ровно в момент интереса.
- Главный экран — **сводка «к выплате» сверху и список сделок**.
- Наставничество по **схеме А**: 5% сверх, из нашей маржи, продавец не теряет
  ничего. Из трёх посчитанных вариантов выбран этот.
- **Автоматической атрибуции нет и не будет:** в white-label версии КП кнопка
  ведёт в личный Telegram партнёра, переговоры идут у него. Деньги считаются от
  СДЕЛОК, а не от кликов.

## 2. 🔴 Что нашёл живой прогон (тесты этого не ловят)

Три дефекта, из них тестами не пойман ни один.

**Списки показывали нули при верных данных.** Начисления считались правильно
(35 000 продавцу и 8 750 наставнику с каждой половины платежа), но список
партнёров и карточка выдавали нули. Тот же SQL руками считал верно:
коррелированный подзапрос `coalesce((select sum(...) where fk = outer.id), 0)`
внутри `.select({})` в drizzle тихо возвращал ноль. Партнёр увидел бы «начислено
0» при оплаченной сделке — спор был бы про деньги, а не про интерфейс. Везде
заменено отдельными группировками со сшивкой через `Map`.

**🔴 Env-ключ в api проходит ПЯТЬ слоёв.** Регистрация партнёра отвечала 404 при
`X10_PARTNERS_ENABLED=1`, подтверждённом `printenv` ВНУТРИ контейнера. Пропущен
был `readBindings` в `apps/api/src/server.ts` — он собирает биндинги из
`process.env` поимённо:

1. `packages/config/src/env.ts` — схема Zod
2. `apps/api/src/bindings.ts` — интерфейс `AppBindings`
3. `apps/api/src/server.ts` — **process.env → биндинги** ← забыл этот
4. `apps/api/src/env.ts` — биндинги → env приложения
5. `docker-compose.prod.yml` — окружение контейнера

Ни типы, ни сборка этого не видят. Закрыто тестом
`apps/api/test/env-wiring.test.ts`: читает ТЕКСТ всех пяти файлов и называет
пропущенный слой по имени.

**Дефект возврата в очередь** (первая половина сессии) — описан в хендоффе 37.

## 4. Грабли сессии

🔴 **`searchParams` нельзя разворачивать на уровне страницы** (Cache Components):
это чтение данных вне Suspense, билд падает целиком. Промис уезжает ВНУТРЬ дыры.

🔴 **Порядок замен в генераторе КП.** Плейсхолдер имени стоит внутри тега `<img>`,
и подстановка имени раньше портрета ломала точное совпадение — фото молча не
вставало, а страница выглядела целой. Добавлена защита: незаменённый
плейсхолдер роняет сборку.

⚠️ **Тест на формулировки проверяет НАЛИЧИЕ правила, а не отсутствие слова.**
Проверка «текст не содержит „взнос"» упала на честной фразе «участие бесплатное:
ни взносов, ни обязательных покупок». Та же грабля, что была с промптом плана.

⚠️ **Импорт `server.ts` в тесте = таймаут.** Тянет весь граф модулей: в одиночку
1,5 с, в общем прогоне больше пяти. Проводку проверяем текстом файлов.

⚠️ **`biome check --write` по каталогу цепляет чужие файлы.** Дважды пришлось
откатывать переформатирование семи посторонних модулей из своего коммита.

⚠️ **Прод-записи и деплой — РАЗНЫЕ разрешения.** Классификатор дважды остановил:
на удалении мёртвых строк и на прогоне, менявшем `username` живого пользователя.
Разрешение на деплой не покрывает запись в чужую строку — и это правильно.
