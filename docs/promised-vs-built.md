## 3. Реестр разрыва

### 3.1 ✅ База знаний клиента — СДЕЛАНО 10.08.2026

**Готово и на проде:** миграция `0024`, экран `/knowledge` (анкета, пока пусто →
полки, когда наполнено), подмешивание в промпт `DraftAgent` шагом
`load-knowledge`. Проверено вживую в кабинете.

Решения, которые надо беречь, — в хендоффе сессии 33 §4.1–4.2. Коротко: полки
вместо папок, ответ и файл — одна сущность, векторного поиска нет намеренно,
бюджет промпта делится между полками поровну, отказ базы не роняет выпуск.

**Осталось на будущее:** загрузка файлов (сегодня только текстовые ответы),
правка материала в интерфейсе (у api PATCH есть, кнопки нет).

#### ✅ База знаний ПО ССЫЛКЕ — построена и выкачена 12.08.2026

Клиент даёт адрес сайта → система обходит до 12 страниц → агент раскладывает
тексты по полкам как **предложения** → человек принимает. Час в анкете
заменяется одной кнопкой.

**Почему это делалось раньше контент-плана.** Замер на проде 10–11.08: 257
опубликованных статей, 11 реакций, **1 материал в базе знаний**. Три прогона
ручного режима подряд показали, что при пустой базе агент пишет про отрасль
вообще, а потом выдумывает конкретику. Промпт — не рычаг, рычаг — вход. У новой
копии клиента база пуста по определению.

Спека и решения: `docs/superpowers/specs/2026-08-11-kb-from-url-design.md`.
Коротко о том, что стоит беречь:

- **Статус `proposed` вместо записи в базу молча.** `loadKnowledge` берёт только
  `ready`, поэтому непринятое предложение физически не может уехать в промпт —
  безопасность держится на уже существующем условии, а не на дисциплине.
- **Один защищённый загрузчик, две обёртки.** `fetchArticle` не мог прочитать ни
  `robots.txt`, ни `sitemap.xml`; вместо второго загрузчика выделен общий
  `fetchSafely`, иначе защиту от SSRF однажды починили бы в одном месте из двух.
- **Бюджет входа 6 000 знаков на страницу.** Без него 12 страниц по 24 000 дают
  288 000 знаков в один промпт.
- **Разбор — отдельный экран, приёмка по полкам** (вариант 1 из трёх). Полка
  отвечает на вопрос «что система знает о моём бизнесе», и непринятое
  предложение сделало бы этот ответ неправдой.

**Выкачено 12.08.2026:** миграции `0028`–`0030` применены, re-sync Inngest
сделан, функция `x10-pipeline-import-knowledge` зарегистрирована.

✅ **Проверено на живом клиентском сайте 13.08** (`zingerlogistic.ru`,
WordPress): 12 страниц, 6 предложений на 6 полках, 1,00 ₽. Цены перенесены

### 3.3 ✅ Контент-план на месяц — СДЕЛАН и выкачен 13.08.2026

**Готово:** миграции `0031`/`0032`, `PlanAgent`, Inngest `build-content-plan`,
маршруты `admin-plan.ts`, экран `/plan` в двух режимах показа (календарь неделя
и месяц · лента по дням). Спека — `docs/superpowers/specs/2026-08-13-content-plan-design.md`.

Решения, которые надо беречь:

- **План не собирается из пустой базы знаний.** Гейт стоит и в api (отказ сразу),
  и в воркере (последний рубеж). Из пустоты вышли бы тридцать тем про отрасль
  вообще — прямой урок сессии 35.
- **Повестка берётся из своих опубликованных статей**, а не из `seen_items`: там
  только отпечатки для дедупа, ни заголовков, ни текстов. Тот же список работает
  стоп-листом.
- **Тема — заготовка задания «Создать»**, а не запись в блокноте: «сделать»
  гонит её общим путём через HumanGate. Второй трубы нет.
- **Недоступный формат отбрасывается, а не подменяется постом.**
- **Пересборка месяца сносит всё, кроме сделанных тем.**
- **Один экран, два режима**, состояние в адресе, карточка темы одна на оба.

**Выкачено 13.08.2026:** миграции `0031`–`0032` применены, re-sync Inngest
сделан, функция `x10-pipeline-build-content-plan` зарегистрирована (функций
стало 15).

⚠️ **Живой прогон не делался.** В нашей базе знаний один материал — гейт
пропустит, но план выйдет тонким. Честная проверка — на копии клиента с
наполненной базой.

⚠️ **Автовыход по плану — вторым шагом** (решение владельца 13.08): сначала
ручное «сделать» по одной теме, чтобы увидеть, годятся ли темы вообще.

### 3.12 ✅ Два дефекта очереди публикаций — ИСПРАВЛЕНЫ 13.08.2026

**Готово и на проде** (`303385e`, миграция `0033` применена, проверено живым
прогоном цикла на боевой строке).

1. Уникальный индекс переехал на `(article_id, channel, format)` — один
   материал живёт в площадке столько раз, сколько у него форматов. Форматы из
   КП: `post · carousel · video · host_video`. Слот забирает ОДНУ строку, то
   есть один формат: материал растягивается на день разными гранями.
2. Состояние строки стало ЯВНЫМ (`queued · posted · rejected`) вместо
   выводимого из `posted_at`. Снятие отмечает человек кнопкой с обязательной
   причиной, снятое возвращается в очередь; причина и время снятия остаются
   навсегда — иначе второй заход выглядел бы первым.

Экран «Постинг» перестал быть одним стоп-краном: там список публикаций
карточками материалов (внутри — строка на каждый формат), фильтр по состоянию,
кнопки «Снято площадкой» и «Вернуть в очередь». Права: смотреть —
`content.view`, отмечать и возвращать — `content.publish`.

⚠️ **Что показал живой прогон и о чём надо знать при разговоре о выпуске:** из
2432 строк «в очереди» слот видит ПЯТЬ. Остальные старше суток — окно свежести
(`POST_SLOT_STALE_HOURS`) их уже не пропустит. Конвейер производит заметно

### 3.13 🟡 Не код, но обещано

- **Оплата частями** — от нас, без банка. Нужен шаблон графика в договоре.
- ~~**Партнёрская программа от 20%**~~ — **УБРАНА ИЗ КП 10.08.2026** решением

### 3.14 🟡 Завал мёртвых строк в очереди — исторический, разобран 13.08.2026

Найдено при живой проверке экрана «Постинг»: 2427 строк из 2432 не выйдут

⚠️ **Поправка к первой оценке:** обложка есть только у 29 материалов из 2427,

📌 **Заодно измерено:** канал получает 13–16 постов в сутки, а не 4. Слоты дают
