## Цель

Каждая статья получает сгенерированную **редакционную иллюстрацию** в брендовом
стиле. Один и тот же URL картинки:
- заменяет текстовый `BrandedCover` обложкой в **ленте Mini App**;
- становится **крупным фото** в посте канала (`sendPhoto`).

## Решения (из брейншторма)

| Развилка | Решение |
|---|---|
| Формат поста в канале | **Крупное фото** + короткая подпись ≤1024 + deep-link кнопка |
| Стиль картинок | **Редакционная иллюстрация** в палитре бренда (red/gold/steel), без текста на картинке |
| Ревью | **Ревью в админке** перед постингом (одобрить / перегенерить / без картинки) |
| Бэкфилл | **Только новые** статьи (текущие ~67 не трогаем) |
| Модель | **Nano Banana 2** = `gemini/gemini-3.1-flash-image-preview` через Timeweb AI Gateway (спайк ✓) |
| Хранилище | **Диск прод-VM + раздача Caddy** (спайк-решение владельца); абстракция под будущий S3 |
| Доступ из РФ | **РЕШЕНО спайком: Timeweb AI Gateway тянет image-модель** → ни Google-ключа, ни прокси |
| Фолбэк | Сбой генерации / нет одобрения к слоту → **текстовый пост** (канал не ждёт) |

## Доступ к модели (§Доступ)

Google `generativelanguage.googleapis.com` геоблокнут из РФ; пайплайн крутится на
VM в Москве.

- **Задача 0 (спайк):** проверить, отдаёт ли Timeweb AI Gateway
  (`api.timeweb.ai/v1`) image-capable модель (Gemini/иную). Требует ключ шлюза.
  - **Да** → генерим через шлюз, прокси не нужен, ключ Google не нужен.
  - **Нет** (вероятно — шлюз DeepSeek-центричный) → **свой тонкий прокси** на
    зарубежном сервере владельца (NL/AMS из других проектов) →
    `generativelanguage.googleapis.com`. `GEMINI_API_KEY` живёт на прокси/в env,
    ключ и промпты не идут через третьи стороны.
- Итог спайка фиксирует, нужен ли `GEMINI_API_KEY` и `GEMINI_PROXY_URL`.

## Архитектура (компоненты)

### 1. VisualAgent (`packages/agents`)
- Вход: `{ tease, lede, category, ключевые факты }` статьи.
- Через `define-agent` (DeepSeek на Timeweb-шлюзе, РФ, дёшево) генерит
  **англоязычный промпт иллюстрации** + фиксированный брендовый стилевой суффикс
  (палитра red/gold/steel, editorial illustration, flat, **no text/letters in
  image** — модели коверкают текст; бренд держим палитрой/композицией/мотивом).
- Выход: `{ imagePrompt: string }`. Сохраняется в `articles.visualPrompt` (для
  перегенерации без повторного крафта).

### 2. Клиент генерации (`apps/workers/pipeline/src/lib/gemini-image.ts`)
- Вызов `gemini-3.1-flash-image-preview` (через шлюз или прокси по итогу спайка).
- Вход: `imagePrompt`; выход: image-байты (PNG/JPEG).
- Per-request timeout, ретрай на 5xx (как у define-agent). Ошибка → бросает →
  вызывающий шаг решает фолбэк.

### 3. Хранилище (`apps/workers/pipeline/src/lib/object-storage.ts`)
- Upload байтов в Timeweb S3 (S3-совместимый API, `@aws-sdk/client-s3` или
  минимальный SigV4-клиент — выбор при плане; **новую зависимость согласовать**).
- Ключ объекта: `covers/<articleId>.jpg`. Возвращает публичный URL.
- URL пишется в `articles.coverImageUrl`.

### 4. Оркестрация (Inngest, `apps/workers/pipeline`)
- Новый шаг после того как статья доведена (`ready`): VisualAgent → генерация →
  S3 → `coverImageUrl` + `visualStatus='pending_review'`.
- Идемпотентность по шагам Inngest (как в пайплайне). Сбой любого шага →
  `visualStatus` НЕ выставляется в approved → фолбэк на текст.
- Новый id функции → re-sync Inngest PUT на pipeline:8787 из контейнера api
  (грабля).

### 5. Ревью в админке (`apps/admin` + `apps/api`)
- Очередь: статьи с `visualStatus='pending_review'` показывают картинку.
- Действия редактора:
  - **Одобрить** → `visualStatus='approved'`.
  - **Перегенерить** → триггер Inngest-события повторной генерации (можно с
    правкой `visualPrompt`).
  - **Без картинки** → `visualStatus='rejected'` (пост уйдёт текстом).
- API-эндпоинты в `apps/api/src/routes/admin*.ts` (паттерн существующих
  admin-мутаций).

### 6. Постинг (`drain-post-slots`)
- При выборе статьи в слот:
  - `visualStatus='approved'` и есть `coverImageUrl` → **`sendPhoto`**
    (`photo=coverImageUrl`, `caption=<b>tease</b>\n\nlede` [+ топ-цифра, ≤1024,
    parse_mode HTML], `reply_markup`=deep-link кнопка из Спеки 1).
  - иначе (`pending_review`/`rejected`/`none`/сбой) → **текстовый пост**
    (`articleToTelegramHtml`, как сейчас) + та же кнопка.
- **Не блокирует** слот: если к моменту слота картинка не одобрена — уходит
  текст, а одобренная картинка позже всё равно служит обложкой в ленте.
- Каптион-лимит 1024 → билдер обрезает по границе слова с «…».

## Схема БД (миграция hand-written + журнал)

- `articles.visualStatus`: varchar + default `'none'`, значения
  `none|generating|pending_review|approved|rejected`. Обратимо (ADD COLUMN).
- `articles.visualPrompt`: text, nullable.
- `articles.coverImageUrl`: **уже существует** (nullable) — переиспользуем.
- ADD COLUMN можно применять mount-migrate без ребилда рантайма (грабля s28), но
  здесь рантайм-код меняется → полноценный `./deploy.sh`.

## Env / bindings (грабля: новый env воркера → `readBindingsFromEnv`)

- `GEMINI_API_KEY`, `GEMINI_BASE_URL` (шлюз или прокси), `GEMINI_IMAGE_MODEL`
  (`gemini-3.1-flash-image-preview`).
- `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PUBLIC_BASE_URL`.
- Все → `@x10/config`-схема (Zod) + `PipelineBindings` + `readBindingsFromEnv`
  (`bindings.ts`) + `docker-compose.prod.yml` + `.env.example`.

## Compliance 152-ФЗ

- Крафт промпта: DeepSeek на Timeweb-шлюзе (РФ-инфра).
- Генерация: Google Gemini — трансгран, но в промпте только производный от
  **публичной новости** текст; **ПДн пользователей отсутствуют** (пайплайн
  работает с публичным контентом, юзеры идентифицируются только Telegram-ID и в
  промпты не попадают). PII-маскировка (Masker) в define-agent — passthrough при
  РФ-шлюзе, для image-пути сохраняем тот же принцип: в промпт ПДн не попадают.
- Хранилище картинок: Timeweb S3 (РФ).
- Итог: трансгран без ПДн — допустимо (CLAUDE.md §7). Зафиксировать в
  `docs/parsing-sources.md` / compliance-заметке.

## Обработка ошибок / фолбэки

| Сбой | Поведение |
|---|---|
| Генерация упала/таймаут | `coverImageUrl=null`, `visualStatus` не approved → текст-пост + `BrandedCover` в ленте (текущее) |
| Прокси/шлюз недоступен | то же |
| S3 upload упал | то же |
| Редактор не успел одобрить к слоту | текст-пост; картинка одобряется позже → обложка в ленте |
| Редактор «без картинки» | `rejected` → текст-пост |
| Каптион > 1024 | обрезка по слову + «…» |

## Тестирование

- Unit: VisualAgent (промпт содержит брендовый суффикс, нет запроса текста на
  картинке); билдер каптиона (≤1024, обрезка по слову); выбор ветки постинга
  (approved→sendPhoto, иначе→текст).
- Unit: S3-клиент (ключ объекта, публичный URL) — с моком.
- Live (после ключа): 1 статья → генерация → S3 URL 200 → админ-ревью →
  `sendPhoto` в тест-канал с кнопкой.
