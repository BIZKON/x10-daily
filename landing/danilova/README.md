бакета + домен раздачи kp + Let's Encrypt во вкладке SSL; CNAME на NS
Timeweb CDN переписывает сам.

🔴 Грабли, за которые уже заплачено:
- Привязка домена к бакету (S3 → Домены) требует CNAME на **голый**
  `s3.twcstorage.ru` ДО привязки — иначе вечный `empty_cname`. После
  смены CNAME привязка через API проходит мгновенно (status: success).
- Панель «Изменить тип бакета» на корень через кастомный домен не влияет
  (пробовали Публичный — корень остаётся AccessDenied).
- Для поддоменов на NS Timeweb CDN сам переписывает CNAME при добавлении
  домена раздачи. Let's Encrypt на CDN не выпускается, пока ресурс
  в «Применяются настройки» («не у всех доменов настроены DNS-записи»).
- В зоне pro-agent-ai.ru жили ТРИ фантомных CNAME для kp (следы попыток
  15.08, API-листинг их не показывал — видно только в панели DNS). Удалены.
- Доступность из ЕС проверена check-host.net 20.08.2026: 200 из Финляндии
  (0,29 с), Швеции, Германии, Нидерландов, Венгрии, Румынии и др.

## Как выложить правку

Бакет `danilova-kp` в Timeweb Object Storage создан S3-клиентом (не `twc`,
иначе к имени добавился бы префикс аккаунта — см. README mobile-kp, там же
все грабли). Адрес не меняется, заливается поверх:

```bash
s3cmd -c ~/.s3cfg-twc put landing/danilova/index.html s3://danilova-kp/index.html \
  --acl-public --mime-type="text/html; charset=utf-8" \
  --add-header="Cache-Control: public, max-age=300"
```

Проверка (кэш 5 минут, добавьте ?v=):

```bash
curl -sS -o /dev/null -w "%{http_code}\n" "https://danilova-kp.website.twcstorage.ru/?v=$(date +%s)"
```

С 20.08.2026 S3-созданные бакеты видны и в панели, и в `twc storage list`
(danilova-kp — id 548081); старое предупреждение о невидимости устарело.
