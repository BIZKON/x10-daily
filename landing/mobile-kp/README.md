# Лендинг «Мобильное приложение с ИИ-агентами» — инструкция

**Живой адрес:** https://mobile-kp.website.twcstorage.ru/

Коммерческое предложение на разработку мобильных приложений с ИИ-агентами:
iOS + Android + RuStore за 800 000 ₽ тремя платежами, сопровождение от 30 000 ₽
в месяц за магазин (40 000 ₽ за оба вместо 60 000).

Собран 15 августа 2026. Показывается трём типам читателей — логистической
компании, институту коучинга и сети массажных салонов, — поэтому отраслевые
блоки идут равными и намёк не читается в лоб.

---

## 🔴 Главное: этот файл НЕ собирается генератором

`landing/index.html` и партнёрские версии в `landing/ivanov`, `landing/kustrya`
и прочих собираются из `landing/kp/template.html` командой
`node scripts/build-kp.mjs`. **Этот лендинг — другой продукт и другая страница.**
Генератор его не трогает, править надо прямо здесь, руками.

`index.html` самодостаточен: ни одного внешнего запроса, все стили и иконки
внутри файла. Открывается двойным щелчком, работает без сервера.

## Как выложить правку

Исходник и то, что лежит на проде, — один и тот же файл. Заливается поверх,
**адрес не меняется**, пересылать ссылку заново не нужно.

```bash
# 1) конфиг для S3-клиента (если ещё нет)
twc storage genconfig --client s3cmd --save ~/.s3cfg-twc

# 2) заливка
s3cmd -c ~/.s3cfg-twc put landing/mobile-kp/index.html s3://mobile-kp/index.html \
  --acl-public --mime-type="text/html; charset=utf-8" \
  --add-header="Cache-Control: public, max-age=300"

# 3) проверка (кэш 5 минут — добавьте ?v=)
curl -sS -o /dev/null -w "%{http_code}\n" "https://mobile-kp.website.twcstorage.ru/?v=$(date +%s)"
```

## Как устроено хранилище и почему именно так

Бакет `mobile-kp` в Timeweb Object Storage, регион ru-1, публичный.

🔴 **Он создан НЕ через `twc storage mb`, а через S3-клиент — и это принципиально.**
Штатный путь упирается в два ограничения:

1. **Промо-тариф за 1 ₽ — один на аккаунт.** Он уже занят бакетом
   `zinger-atec-audit`. `twc storage mb --preset-id 4611` отвечает
   `promo_storage_already_exist`, следующий тариф — 99 ₽/мес.
2. **`twc` добавляет к имени префикс аккаунта** (`c7a04e58-mobile-kp`), и он
   попадает в адрес. В документации CLI прямо сказано: **при создании через
   S3-клиент префикс не добавляется.**

Поэтому:

```bash
# ⚠️ bucket_location в конфиге = ru-1, а S3 API его не принимает:
#    "The ru-1 location constraint is not valid" — регион надо передать пустым
s3cmd -c ~/.s3cfg-twc --bucket-location="" mb s3://mobile-kp

# 🔴 и обязательно включить веб-хостинг, иначе корень отдаёт 404,
#    работает только полный путь до объекта
s3cmd -c ~/.s3cfg-twc ws-create --ws-index=index.html s3://mobile-kp
```

⚠️ Бакет, созданный через S3-клиент, **не виден в панели и в `twc storage list`** —
инвентарь Timeweb о нём не знает. Управлять им можно только S3-клиентом.
Команда `ws-info` показывает в ответе адрес вида `…s3-website-ru.amazonaws.com` —
это s3cmd угадывает по шаблону AWS, **реальный адрес другой**, тот, что вверху.

## Грабли, за которые уже заплачено

- **Свой домен к бакету через API не привязывается.** `POST /storages/buckets/{id}/subdomains`
  отвечает `200 OK` и тут же `status: failed`, а после снятия конфликта —
  `empty_cname`. Причина: их же API создаёт CNAME (`201 Created`), но в
  `GET /domains/{fqdn}/dns-records` записи потом **нет** — валидатор смотрит в тот
  же неполный список и не находит. Делается только через панель. Это тот же
  случай, что с доменами App Platform.
- **DNS-запись для поддомена заводится на РОДИТЕЛЬСКОМ домене** с полем
  `subdomain`, а не на самом поддомене. `POST /domains/kp.pro-agent-ai.ru/dns-records`
  → `bad_subdomain_name`; `POST /domains/pro-agent-ai.ru/dns-records`
  с `{"subdomain":"kp"}` → `201`.
- **Кодировка.** Заливать только с `--mime-type="text/html; charset=utf-8"`.
  Без неё кириллица превращается в кракозябры, и это не видно, пока не откроешь.
- **Два раза за сборку ловились ошибки каскада, которых не видно замерами:**
  `.hero>*{position:relative}` перебивал `position:absolute` у декоративных пятен
  (пятна вставали в поток и утапливали заголовок на 1159 px), а `.cta a{background:#fff}`
  красил телефон в подписи белым по белому. **Оба нашлись только скриншотом.**
  После правки вёрстки — снимать картинку, а не только мерить геометрию.
- **Макеты телефонов посчитаны от реального устройства:** логическое разрешение
  iPhone 402 × 874 pt, экран в макете 252 × 548 (та же пропорция 2.174), «остров»
  78 × 23 с отступом 7, радиус экрана 34, таб-бар 49 pt плюс зона жеста 34 pt.
  Менять размеры — пересчитывать всё вместе, иначе корпус перестаёт читаться
  как iPhone.
- **Экраны обрезаются молча.** У `.body` стоит `overflow:hidden`; если контента
  больше высоты, низ вместе с таб-баром просто исчезает. Проверять так:
  `[...document.querySelectorAll('.screen .body')].map(b=>b.scrollHeight-b.clientHeight)`
  — все значения должны быть 0.

## Что в странице осознанно НЕ настоящее

**Цифры в кабине РОПа — иллюстративные.** Решение владельца 15.08.2026: настоящие
показатели называть голосом на встрече, но не публиковать.

Причина: страница называет «Зингер Логистику» кейсом, а боевые цифры показали бы
её выручку и отток. Клиент, подходящий под сигнал «выручка упала вдвое, но ещё
заказывает», в базе **ровно один** — то есть по цифрам его опознали бы и внутри
Зингера, и он сам. Согласие было на упоминание кейса, не на публикацию
показателей.

Настоящие цифры на 15.08.2026 (для разговора, не для страницы): потеря за
квартал 794 152 ₽ при нуле опозданий; портрет клиента — цена 85, скорость 20,
надёжность 25, реакция на проблемы «уходит молча»; два молчащих с LTV 5 175 685
и 4 187 628 ₽; 680 профилей с оценками и 70 319 фактов о клиентах.
